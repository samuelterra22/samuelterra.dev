# Prompt para o Claude Code

Descompacte o kit na raiz do repositório do site atual, abra o `claude` nessa pasta e cole o texto abaixo. Depois que o trabalho terminar, apague este arquivo.

---

Este repositório hospeda samuelterra.dev, hoje uma página única. Vou substituí-lo por um site novo em Astro 6, estático, com a seção de artigos descrita em docs/proposal.md. O kit já está descompactado na raiz: CLAUDE.md, docs/, .claude/skills/, astro.config.mjs, tsconfig.json, src/styles/, src/content.config.ts, src/lib/labels.ts, os templates em src/content/, os SVGs de marca em src/assets/brand/, public/favicon.svg e as cinco fontes em public/fonts/. Leia CLAUDE.md e docs/brand.md antes de começar, e docs/components.md antes de qualquer componente.

Trabalhe por fases, com um commit no fim de cada uma (conventional commits, em inglês). Não me pergunte entre as fases; pare só para pedir credencial, para fazer push ou se algo nas regras abaixo for impossível. Texto visível em português, código em inglês, como diz o CLAUDE.md.

Fase 0, inventário e preservação. Descubra a stack do site atual, como ele é construído e onde é publicado (procure package.json, vercel.json, netlify.toml, wrangler.toml, _redirects, CNAME, .github/workflows, Dockerfile). Resuma em dez linhas. Crie a branch legacy e a tag legacy-2026-10 a partir do estado atual, sem push. Volte para a branch principal. Guarde src/assets/brand/avatar.png (ou o nome que a foto tiver) se existir uma foto do Samuel no site antigo, e guarde a configuração de deploy que ainda servir para um site estático; o resto do site antigo sai do diretório de trabalho (está na branch legacy). Não apague .git, .gitignore nem os arquivos do kit.

Fase 1, projeto Astro. Confira Node 22 ou mais novo. Crie um package.json novo (name samuelterra.dev, type module, scripts dev, build, preview e check com astro check) e instale astro, @astrojs/mdx, @astrojs/sitemap, @astrojs/rss, astro-expressive-code, tailwindcss, @tailwindcss/vite, sharp, pagefind, satori, @resvg/resvg-js, @astrojs/check e typescript, nas versões estáveis atuais. Mantenha astro.config.mjs e tsconfig.json do kit; se alguma opção deles não existir na versão instalada, ajuste a opção e me diga qual foi. Faça um .gitignore para node_modules, dist e .astro. Crie uma página index mínima e rode npm run build e npx astro check até passarem limpos.

Fase 2, layout e componentes. src/layouts/Base.astro com cabeçalho (nome completo em serifa, menu com os rótulos de src/lib/labels.ts, domínio em mono no celular), rodapé (RSS, GitHub, LinkedIn, link "Volpa" para a empresa, botão de tema) e um script inline no head que lê o tema de localStorage ou de prefers-color-scheme e grava data-theme em html antes da pintura. src/layouts/Article.astro com coluna de 68 caracteres e sumário fixo à esquerda no desktop. Componentes Seo, Level, MetaBar, ArticleCard, ForBeginners, PlainWords, Toc e Button seguindo docs/components.md ao pé da letra; o expressive-code já está configurado no astro.config.mjs. Sem framework de UI e sem JavaScript além do tema, da busca e do botão de copiar.

Fase 3, páginas. index, about (a partir de docs/bio.md; o que estiver marcado como "a confirmar" vira um comentário no código, não texto publicado), articles com filtros por tema, nível e tipo e busca com Pagefind, articles/[slug], articles/notes/[slug], articles/paths/[slug], articles/topic/[topic], articles/level/[level], articles/glossary (lendo src/content/glossary.json, que você cria vazio com o formato termo e definição), projects e projects/[slug], research (lendo a coleção publications), now, contact e 404. Rascunhos nunca aparecem, nem em desenvolvimento.

Fase 4, SEO. Seo.astro com title, description, canonical, Open Graph e JSON-LD: Person com sameAs na home e em about, TechArticle em artigos e notas, ScholarlyArticle em research, BreadcrumbList em tudo. rss.xml, sitemap pelo integration, public/robots.txt apontando o sitemap. Imagem de compartilhamento 1200×630 por artigo e nota gerada na build com satori e resvg, reproduzindo o layout de src/assets/brand/og-template.svg com as fontes de public/fonts; a rota é /og/<slug>.png.

Fase 5, conteúdo de teste. A partir de src/content/articles/_template.mdx, crie um artigo, uma nota e uma trilha com draft: true e texto de exemplo que use todos os componentes, só para eu ver o site inteiro funcionando; não escreva conteúdo real, isso é feito pelo skill new-article comigo. Em projects, crie três entradas com draft: true a partir de docs/bio.md (Sopro, o chatbot de WhatsApp em n8n e os pacotes Laravel), deixando repo e url vazios. Para a conferência local, suba o servidor com rascunhos visíveis por uma variável de ambiente SHOW_DRAFTS=true e depois confirme que, sem ela, nada de rascunho aparece.

Fase 6, publicação. Se o site antigo já é publicado por Cloudflare Pages, Vercel ou Netlify, ajuste a configuração para o build do Astro (comando npm run build, saída dist) e me diga o que mudou; se era GitHub Pages ou outra coisa, prepare o projeto para o Cloudflare Pages e me diga o que eu preciso fazer no painel e no DNS. Não faça deploy nem push: eu faço.

Fase 7, conferência. npm run build e npx astro check limpos; npm run preview no ar; cada página com um único h1, lang pt-BR, title e description únicos; contraste e foco visível conferidos nos dois temas. Termine com um relatório curto: o que ficou pronto, o que você ajustou do kit, o que depende de mim (DNS, Search Console, dados marcados como "a confirmar" em docs/bio.md) e os comandos para subir o site.
